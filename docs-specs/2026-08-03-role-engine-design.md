# 角色运行引擎（Role Engine）设计文档

> 日期：2026-08-03 ｜ 目标角色：大帅（dashuai）｜ 状态：阶段一/阶段二均已实现

## 背景与问题

当前「大帅」只有静态人设（config.json 的 persona 字符串），每次对话仅携带最近 20 条历史。
缺陷：

1. **无长期记忆**：聊完就忘，隔天接不上茬。
2. **无状态**：情绪、精力恒为默认，语气一成不变。
3. **无时间感**：不知道现在是几点、星期几、有没有比赛安排。
4. **无主动性**：只能被动应答，不会主动开口。

用户确认：长期记忆、生活节奏、情绪状态、主动互动四块能力全都要，采用「方案三：渐进式」。

## 架构总览

```
用户消息
  │
  ├─ 时间层   → 生成"此刻上下文"（几点/星期几/日程）
  ├─ 状态层   → 读情绪/精力/亲密度 → 语气描述
  ├─ 记忆层   → 检索最相关 3~5 条长期记忆
  ├─ 组装 system prompt（persona + 三层上下文 + 原有输出协议）
  │
  └─ 回复后（异步，不阻塞主链路）
       └─ 轻量 LLM 调用抽取 {情绪变化, 新事实} → 写回状态库 + 记忆库
```

**阶段一（已实现）**：后端角色引擎，前端零改动。
**阶段二（已实现）**：`/api/greeting` + 前端心跳主动问候。

## 模块设计：`role_engine.py`（server.py 同目录）

### 1. 记忆库 `data/memory/{role}.json`

```json
{
  "version": 1,
  "memories": [
    {
      "id": "uuid",
      "text": "老公最近在练杨玉环",
      "importance": 0.8,
      "tags": ["老公", "游戏", "杨玉环"],
      "created_at": "2026-08-03T10:00:00+08:00",
      "last_hit": "2026-08-03T10:00:00+08:00",
      "hit_count": 1
    }
  ]
}
```

- 写入前**语义去重**：2/3-gram Jaccard 相似度 ≥ 0.5 且长度比在合理区间（更新旧条目而非新增）。
- 上限 **200 条**，超出按「importance × 新鲜度衰减」裁剪最旧。
- 检索打分：`0.5×关键词命中 + 0.3×importance + 0.2×新鲜度(最后命中时间)`，取 top 5。

### 2. 状态库 `data/state/{role}.json`

```json
{
  "version": 1,
  "emotion": { "valence": 0.3, "arousal": 0.2 },
  "energy": 0.7,
  "intimacy": 0.5,
  "last_update": "2026-08-03T10:00:00+08:00"
}
```

- 情绪 = valence（-1 难过 ~ 1 开心）+ arousal（0 平静 ~ 1 激动）。
- **平滑移动**：每次后处理标注最多移动 0.2，防止变脸。
- **自然衰减**：距上次更新时间超过 2h，情绪向基线（valence 0.2, arousal 0.3）靠拢，速率 0.1/h。
- 亲密度：随互动缓慢增长，封顶 1.0。

### 3. 时间层（内置日程）

- 生成真实时间上下文：星期几、几点、是否为训练日/比赛日。
- 默认日程（可被记忆覆盖）：
  - 周一到周五：下午训练、晚间复盘。
  - 周六日：比赛日或直播日。
- 注入示例：`此刻是周一 21:00，你刚复盘完今天的训练赛。`

### 4. 后处理（异步，不阻塞主链路）

- 单次轻量 LLM 调用，输入：用户消息 + 大帅回复 + 当前状态。
- 输出 JSON：`{ "emotion": {"valence": x, "arousal": y}, "memories": ["新事实1", "新事实2"], "energy_delta": 0.05 }`。
- 失败（超时/解析错误）→ 静默跳过，不阻塞、不报错。
- 用与主对话相同的 provider，但 `temperature=0.3, max_tokens=300`。

### 5. 上下文注入格式（拼进 system prompt）

```
【此刻上下文】
现在是 2026-08-03 周一 21:00。你刚结束今天的训练和复盘，有点累但心情不错。

【你的状态】
你现在的情绪：平静中带点开心。精力：有些疲惫。
你们的关系：已经很亲密。

【你能想起的事】
- 上次老公说过他在练杨玉环，你建议他把三段拍练熟。
- 老公前几天抱怨过训练太多陪他时间少。
```

规则：注入的是「他能想起的事」，不是让他在回复里逐条复述；由模型自然带出。

### 6. 安全与降级

- `config.json` 新增 `role_engine: { enabled: true, memory_limit: 200, top_k: 5 }`，`enabled=false` 时完全退回旧行为。
- 记忆/状态文件损坏 → 自动重置为空库，不阻塞对话。
- 后处理 LLM 调用失败 → 静默跳过。
- 记忆写入并发安全（复用 server 的 `_io_locks` 模式，独立锁）。

### 7. API 变更

- `/api/chat`：内部流水线变化，响应结构不变（`{reply, style}`）。
- 新增 `/api/state`（GET）：返回当前角色状态（情绪/精力/亲密度/记忆数），前端与调试可用。
- 新增 `/api/state`（DELETE 或 `?reset=1`）：重置状态与记忆（调试用）。
- 新增 `/api/greeting`（POST）：基于时间/状态/记忆生成主动问候，不触发后处理；前端每天最多触发 1 次，距上次聊天 2 小时内不触发。

## 验证方案

1. **单元测试** `test_role_engine.py`：
   - 记忆写入去重（同义句不重复入库）。
   - 检索排序（关键词命中 > importance > 新鲜度）。
   - 记忆裁剪（>200 条时最旧被裁）。
   - 情绪平滑（delta ≤ 0.2）。
   - 情绪衰减（2h 后回归基线）。
   - 时间上下文生成（训练日/周末不同文案）。
2. **端到端**：真实对话 3 轮验证「接得上茬」（先让模型记住一个事实，隔轮提问确认能带出）。
3. **降级验证**：`enabled=false` 时行为与改动前一致。
4. **主动问候**：`/api/greeting` 返回自然开场白；前端心跳的开关/每日 1 次/2 小时内不触发均已实测。

## 明确不做（YAGNI）

- 不做向量数据库（200 条以内关键词+打分足够）。
- 不做人格成长/技能树（超出本次范围）。
- 前端心跳主动问候已在阶段二实现（`/api/greeting` + 每日频率控制），不再属于 YAGNI。
