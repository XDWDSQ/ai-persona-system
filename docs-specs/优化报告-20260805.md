## 0. 代码体检结论（先说结论）

这套代码的**基础质量高于一般项目**：已有 mtime 失效缓存（config/sessions）、线程池防阻塞（to_thread）、原子写盘（tmp+replace）、SSE 攒批帧率控制、多端墓碑合并、登录退避、上传白名单+流式落盘等。因此本次优化不是"推倒重来"，而是**消除剩余热点**：每次请求的重复读盘/深拷贝、静态资源无压缩、会话文件全量读解析、前端渲染重复建 DOM、渲染阻塞的外部字体。

| 维度 | 体检结果 |
|------|----------|
| 接口响应时间 | 每次 chat 请求链路内重复 load_config 3-4 次（每次含全量深拷贝+env 合并）；location/role_news 各读盘 1 次 |
| 数据库/存储查询效率 | 项目为 JSON 文件存储（无数据库）：sessions PUT 每次全量读+解析整个文件；记忆/状态每次 chat 重读盘 |
| 并发处理 | 后台任务无上限保护；多端同步 SSE 已正确（队列满丢弃、15s 保活） |
| 错误处理 | 无全局兜底处理器，未捕获异常返回 FastAPI 默认 500，无统一日志 |
| 前端加载速度 | 5 页均渲染阻塞式加载 Google Fonts（国内网络慢/失败会拖慢首屏）；静态资源无 gzip 压缩 |
| 前端渲染性能 | 每次收发消息全量重建会话列表 DOM；切会话逐条 append 消息（多消息时多次布局） |
| 安全 | 整体扎实（cookie HttpOnly+SameSite、登录退避、跨源兜底、上传白名单）。本次补：安全响应头；确认无 SVG 上传 XSS 面 |

## 1. 后端优化明细（含前后对比与代码示例）

### 1.1 chat 链路配置重复加载 → 全链路复用 + 缓存（接口响应时间）

**优化前**：一次 chat 请求链路内 `load_config()` 被调用 3-4 次（chat → llm_chat/llm_chat_stream → 搜索轮/长文续写/退化重试），每次调用都 `copy.deepcopy` 整个配置（含数 KB 人设）并遍历全部 env 变量做密钥合并。

**优化后**：
- `llm_chat` / `llm_chat_stream` / `_extend_long_form` 增加 `cfg` 可选参数，调用方传入后不再内部加载；
- `_apply_env_overrides` 的合并结果按 `(config mtime, env 值签名, cfg 对象身份)` 缓存，命中时零深拷贝、零 env 遍历。

**验证**：模拟带搜索+重试的完整链路，`load_config` 调用次数 **3-4 次 → 0 次**。

```python
# 优化后（server.py）——缓存键设计，env 不变 + 配置未改 + 同一对象即复用
_env_override_cache: dict = {"key": None, "value": None}

def _apply_env_overrides(cfg: dict, mtime_ns: int = 0) -> dict:
    sig = _env_override_signature()
    ck = (mtime_ns, sig, id(cfg))          # 对象身份参与键：不同 cfg 绝不串缓存
    if _env_override_cache["key"] == ck and _env_override_cache["value"] is not None:
        return _env_override_cache["value"]
    out = copy.deepcopy(cfg)               # 仅缓存未命中时深拷贝
    ...  # 原 env 合并逻辑不变
    _env_override_cache["key"] = ck
    _env_override_cache["value"] = out
    return out
```

### 1.2 位置/角色动态每次读盘 → mtime 失效缓存（接口响应时间）

**优化前**：`_location_summary()`（chat 每次调用）→ `_load_auto_location()` 读盘+解析 `location.json`；`_role_news_text()` → `_load_role_news()` 读盘+解析 `role_news.json`。一次对话 2 次磁盘 IO。

**优化后**：统一 `_memo_file_json(path, default)` 工具（stat mtime 命中即返回缓存对象，写盘后 `_invalidate_memo` 失效）。chat 请求命中缓存时 **2 次读盘 → 0 次**。

```python
_small_file_cache: dict[str, tuple[int, dict]] = {}

def _memo_file_json(path: Path, default: dict) -> dict:
    try:
        mtime = path.stat().st_mtime_ns
    except OSError:
        return dict(default)
    hit = _small_file_cache.get(str(path))
    if hit is not None and hit[0] == mtime:
        return hit[1]
    try:
        data = json.loads(path.read_text(encoding="utf-8"))
    except (json.JSONDecodeError, OSError, UnicodeDecodeError):
        return dict(default)
    if not isinstance(data, dict):
        return dict(default)
    _small_file_cache[str(path)] = (mtime, data)
    return data
```

### 1.3 会话保存全量读+解析 → 内存基底（存储查询效率）

**优化前**：`PUT /api/sessions` 每次把整个 sessions.json（多端同步下可达数 MB）读入内存再 json.loads，然后合并、序列化、写回。

**优化后**：磁盘 mtime 与 `_sess_cache` 一致时（本进程内正常写入路径），直接用内存缓存里的完整状态做合并基底，**省掉一次全量读盘+JSON 解析**；mtime 不一致（外部修改）才回退读盘，行为完全一致。

### 1.4 记忆/状态存储读取 → mtime 缓存（存储查询效率）

**优化前**：`MemoryStore.search()` 每次 load 全量记忆文件；`StateStore.get_decayed()` 每次 load 状态文件——chat 主链路每请求各读盘一次（记忆命中后 touch 再读一次）。

**优化后**：两个 Store 增加 `_cache: (mtime_ns, 原始数据)`，`load()` 命中缓存零读盘；`_save()` 后显式失效。`MemoryStore.load()` 返回浅拷贝副本（touch 原地修改不污染缓存），`StateStore.load()` 本就在副本上构建 merged（天然安全）。

```python
class MemoryStore:
    def _load_cached(self) -> dict:
        try:
            mtime = self.path.stat().st_mtime_ns
        except OSError:
            self._cache = None
            return {"version": 1, "memories": []}
        if self._cache is not None and self._cache[0] == mtime:
            return self._cache[1]
        data = _safe_load(self.path, {"version": 1, "memories": []})
        self._cache = (mtime, data)
        return data

    def load(self) -> list[dict]:
        data = self._load_cached()
        mems = data.get("memories", [])
        if not isinstance(mems, list):
            return []
        return [dict(m) if isinstance(m, dict) else m for m in mems]  # 浅拷贝，防污染
```

### 1.5 静态资源无压缩 → gzip（页面加载速度，收益最大项）

**优化前**：chat.html 原始体积 222 KB，走 `Cache-Control: no-cache` 每次全量传输；JSON API 同样明文传输。

**优化后**：新增 gzip 中间件——只压缩白名单类型（text/html、text/css、application/javascript、application/json、image/svg+xml），只压缩有 Content-Length 且 512B~8MB 区间的响应，**SSE 流（text/event-stream）天然排除，绝不缓冲**。

**实测对比**：

| 资源 | 优化前 | 优化后 | 节省 |
|------|--------|--------|------|
| chat.html | 222,349 B | 53,503 B | **76%** |
| index.html | 57,433 B | 12,673 B | **78%** |
| SSE 首帧 | — | 不被压缩，首帧即时到达（实测 0.00s） | 无缓冲 |

```python
_GZIP_CONTENT_TYPES = {"text/html", "text/css", "text/plain", "application/javascript",
                       "application/json", "image/svg+xml"}

@app.middleware("http")
async def gzip_and_security_headers(request: Request, call_next):
    response = await call_next(request)
    ...
    if ctype not in _GZIP_CONTENT_TYPES:      # SSE 等流式/二进制一律跳过
        return response
    ...  # 有 Content-Length 且 < 8MB 才压缩，防大文件/无限流整段读内存
    compressed = gzip.compress(body, compresslevel=6)
    if len(compressed) >= len(body):          # 压缩无收益回退原样
        return Response(body, ...)
    response.headers["content-encoding"] = "gzip"
    response.headers["content-length"] = str(len(compressed))
    ...  # Vary 头正确追加 Accept-Encoding
```

### 1.6 错误处理机制补强

**优化前**：未捕获异常由 FastAPI 返回默认 `{"detail":"Internal Server Error"}`，服务端无统一日志记录，远程排障只能看 uvicorn 原始输出。

**优化后**：全局异常兜底处理器——记录完整 traceback（含请求方法/路径），返回统一 JSON（不泄露内部细节）；SSE 流内错误仍由各生成器自行处理，不受影响。

```python
@app.exception_handler(Exception)
async def _unhandled_exception_handler(request: Request, exc: Exception):
    _log.error("unhandled exception on %s %s: %s",
               request.method, request.url.path, exc, exc_info=True)
    return JSONResponse({"detail": "服务器内部错误，请稍后重试"}, status_code=500)
```

### 1.7 并发与资源保护

**优化前**：`_spawn_bg` 创建的后台任务集合无上限，异常场景（模型持续超时堆积后处理任务）可能无限增长。

**优化后**：任务积压上限 200，达到上限丢弃新任务并告警，防进程拖垮。

### 1.8 安全响应头

所有响应统一追加 `X-Content-Type-Options: nosniff`（防 MIME 嗅探）、`Referrer-Policy: no-referrer`（防泄漏 URL 参数）、`X-Frame-Options: SAMEORIGIN`（防点击劫持）。幂等 setdefault，不覆盖已有值。

**安全复核结论（既有代码已正确，无需改动）**：上传后缀白名单不含 SVG（无存储型 XSS 面）；口令 cookie HttpOnly+SameSite=Lax；登录失败固定 1s 退避；无口令模式拒绝跨源 Origin；provider 密钥经 `***+尾4` 掩码（无口令时）。本次修复中确认：门禁在全新连接下无 cookie 访问 API 返回 401（实测验证）。

## 2. 前端优化明细（含前后对比与代码示例）

### 2.1 Google Fonts 渲染阻塞 → 异步加载（页面加载速度）

**优化前**：5 个页面均以 `<link rel="stylesheet">` 同步加载 `fonts.googleapis.com`，是 render-blocking 资源；国内网络下该请求慢/失败会直接拖慢首屏渲染。

**优化后**：改为 `rel="preload" as="style"` + `onload` 切换 + `<noscript>` 兜底的标准异步模式——HTML 解析不再被字体请求阻塞，字体加载完成后自动应用（font-display:swap 保证文字先以系统字体显示，不闪白屏）。

```html
<!-- 优化前（渲染阻塞） -->
<link href="https://fonts.googleapis.com/css2?family=Geist:..." rel="stylesheet">

<!-- 优化后（异步加载，不阻塞首屏） -->
<link rel="preload" href="https://fonts.googleapis.com/css2?family=Geist:..." as="style"
      onload="this.onload=null;this.rel='stylesheet'">
<noscript><link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Geist:..."></noscript>
```

### 2.2 会话列表全量重建 → 指纹比对 + 文档片段（渲染性能）

**优化前**：`renderSessions()` 每次调用都清空并逐个重建全部会话按钮——而 `markSessionActivity` 在**每条**消息收发时都会触发它，连续对话时列表 DOM 被反复全量重建。

**优化后**：先用轻量指纹串（id/置顶/标题/活跃时间/选中态）比对，**内容未变直接跳过渲染**；真正需要重绘时用 `DocumentFragment` 批量挂载，几十个会话只触发一次布局。

```js
var sessionsRenderKey = '';
function renderSessions() {
  if (!sessionsBox) return;
  var key = sortSessions(sessions).map(function(x){
    return x.id + '|' + (x.pinned ? 1 : 0) + '|' + (x.title || '') + '|'
         + (x.updatedAt || 0) + '|' + (x.id === currentSessionId ? 1 : 0);
  }).join('~');
  if (key === sessionsRenderKey && sessionsBox.childNodes.length) return;  // 无变化跳过
  sessionsRenderKey = key;
  sessionsBox.innerHTML = '';
  var frag = document.createDocumentFragment();   // 批量挂载，一次布局
  sortSessions(sessions).forEach(function(session, idx){ ... frag.appendChild(s); });
  sessionsBox.appendChild(frag);
}
```

### 2.3 历史消息逐条挂载 → 文档片段（渲染性能）

**优化前**：切换会话时 `renderCurrentSession` 逐条 `addMsg` 直接 append 到消息容器，几十上百条消息触发多次布局/重绘。

**优化后**：`addMsg` 支持 `opts.container`，历史渲染统一挂进 `DocumentFragment` 后一次性提交（滚动、入场动画、右键菜单等行为完全不变）。

```js
var frag = document.createDocumentFragment();
(state.history || []).forEach(function(m, i){
  var div = addMsg(m.role, m.content, {
    delay: animOn ? Math.min(i * 45, 400) : 0, noScroll: true,
    attachments: m.attachments || [], animate: animOn,
    container: frag                       // 挂到 fragment，最后统一提交
  });
  ...
});
msgsInner.appendChild(frag);
```
