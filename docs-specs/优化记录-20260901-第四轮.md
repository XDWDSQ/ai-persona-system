## 一、本轮完成项

### 1. 人设单一真值（消除 config.json 顶层 persona 重复）⭐ 本轮核心

**问题**：`config.json` 顶层 `"persona"` 与 `roles.dashuai.persona` 各存一份 **3293 字符的完全相同文本**。虽然后端写路径做了双写同步防止漂移，但：
- 文件里两份大段重复，手改一份忘另一份时行为会很怪（存量双写正是 08-29 报告的待办项）
- 顶层 persona 实际没有任何读路径依赖（所有读取都走 `current_persona()`，角色 persona 优先）

**改动**：
| 文件 | 改动 |
|---|---|
| `server.py` | `_merge_config_update`：人设保存**只写角色 persona**；仅当无角色（遗留配置）时才写顶层兜底 |
| `server.py` | `roles_apply`：切角色不再把 persona 复制到顶层；返回值改为从角色读取 |
| `config.json` | 删除顶层 `"persona"` 重复块（角色 persona 保留为唯一真值） |
| `config.example.json` | 同步删除顶层 `"persona"` |
| `test_config_api.py` | `test_persona_double_write` → `test_persona_single_source`：断言角色 persona 更新、顶层不再被写、无角色时顶层兜底写入 |

**验证**：`current_persona()` 全读路径不受影响（chat/greeting/status 均走此函数）；离线测试 9/9 全绿。

## 四、明确跳过（基于收益/风险判断）

- **server.py 拆模块**：纯代码搬家、接口零变化、用户零感知，回归风险大于收益——维持 08-29 结论，不做
- **dashuai 专属逻辑参数化**（`_fix_addressing` / `_STYLE_HINT` / 4 处 `if active_role == "dashuai"`）：功能上已被守卫正确隔离，重构只改善代码观感、不改变行为，且当前唯一在用角色就是 dashuai——等出现第二个需要后处理的角色再做
- **data/uploads 重复附件清理**：删附件会破坏 sessions.json 中的图片引用，收益低风险高，不动
- **虚拟列表 / 前端框架化 / 数据库**：当前规模收益为零，持续维持"不做"结论
