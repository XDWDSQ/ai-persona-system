# 第八轮全面优化记录（2026-09-23，后端专场）

范围：后端「加量不加价」——不加硬件、不增加 API 调用，提升性能/稳定性/安全性/可观测性。
基线：第七轮后 17 套离线测试 + 21 项运行时冒烟全绿。
本轮结束后 **18 套离线测试（新增 test_backend_hardening 38 项）+ 21 项运行时冒烟全绿**。
共 21 项改动。改动文件：`server.py`、`qa_run.py`、`conftest.py`、`run_tests.bat`、
新增 `test_backend_hardening.py`，以及 7 个测试文件补的离线开关/隔离。

---

## 一、真实 Bug（前端容错掩盖了它）

1. **重启后首次会话指纹轮询必 500**。`GET /api/sessions/fingerprint` 在进程缓存为空
   （服务刚重启）时调 `await get_sessions()` 想预热缓存，但 `get_sessions` 必填
   `request` 参数 —— 每次重启后的第一次轮询必抛 `TypeError: get_sessions() missing 1
   required positional argument: 'request'`。前端 catch 后退回全量拉取，**正好浪费掉
   指纹端点设计出来要省的那次数 MB 流量**；既有测试先 PUT 再查指纹，缓存总是热的，
   从未覆盖冷启动路径。改为调无参的 `_read_sessions_cached()`，新增「旧行为必失败」
   回归（空缓存 + 磁盘有文件 → 200 且指纹与全量一致）。
2. `_read_sessions_cached` 对 `_sess_cache["_mtime_ns"]` 的下标访问改 `.get()`：
   一旦缓存 dict 被清空/结构异常就是 KeyError 500，与同文件其他位置的 `.get` 写法对齐。

## 二、性能（零成本，云盘部署环境收益明显）

3. **`load_config` 的 stat 加 250ms 短 TTL**。一轮对话链路上 `load_config` 被调用
   十几次（chat → `_story_role`/`_location_city`/`_weather_enabled`/`_self_hint`/
   `_role_news_config`…），旧实现每次都向文件系统发一次 `stat`。本项目跑在移动云盘
   同步盘上，单 stat 比本地盘慢一个量级，是每轮对话固定的无谓开销。250ms 内复用
   mtime；本进程保存配置走 `save_config` 直接更新内存并主动刷新该 TTL（立即生效），
   只有「外部手改 config.json」最坏延迟 250ms 被发现。回归：50 次连续读取只发 1 次 stat。
4. **大会话 JSON 序列化移出事件循环**。`GET /api/sessions` 旧实现用 `JSONResponse`
   在事件循环线程里同步 `json.dumps`（sessions.json 上限 32MB），多端轮询/重载期间
   会冻住全场 SSE 心跳与其他请求。改为线程池预渲染 bytes。
5. **会话 JSON 不再 ASCII 转义**。序列化改 `ensure_ascii=False`：中文按 UTF-8 原文
   输出（旧实现 `\uXXXX` 每字 6 字节），非压缩通道体积直接减半；JSON 标准默认 UTF-8，
   前端解析零差异。端到端实测：含 6 万中文的响应 identity 通道 129KB，gzip 后 1.5KB。
6. **gzip 压缩移出事件循环**。32MB 文本 level 6 压缩可达秒级 CPU，旧实现直接在事件
   循环上压；改 `asyncio.to_thread`。同时压缩上限 8MB → 33MB（对齐 sessions 的 32MB
   上限）——旧上限让最该压缩的大会话全量响应绕过了压缩。
7. **`/api/status` 脱敏响应按配置对象身份缓存**。前端高频轮询该端点，旧实现每次
   `deepcopy` 整份 config（角色人设数千字）+ 递归脱敏。load_config 在
   (mtime, env 签名) 不变时返回同一对象，按 `id(cfg)` 缓存脱敏成品即可，配置一变
   （保存/换角色）对象身份即变自动失效；音色注册状态是 `exists()` 结果不进缓存，
   仍每次实时组装。回归验证脱敏绝不污染配置真值。
8. **云端 TTS 音频解码移出事件循环**：阿里云/MiMo 的 `base64.b64decode`、MiniMax 的
   `bytes.fromhex`（长文本音频可达数 MB 纯 CPU），以及本地 TTS 参考文本的同步读盘，
   一律 `to_thread`，不再卡 SSE 心跳。
9. **`/api/health` 的缓存目录文件计数加 5s TTL**：探活/监控高频打 health 时不再每次
   `iterdir` 数百文件；缓存清理后由清理逻辑主动刷新计数。
10. **HEIC/AVIF opener 全局只注册一次**：旧实现每次图片转码都重复 `register_heif_opener`。

## 三、稳定性（磁盘/资源泄漏与有界保护）

11. **OUTPUT_DIR 孤儿音频回收（此前完全没有清理）**。云端/本地 TTS 的成功产物都会被
    原子搬进 `tts_cache`，留在 `data/outputs` 的 `tts_*.wav/.mp3` 只可能是异常路径产物
    （客户端中途取消、合成失败、GMI 转码中断的中间 mp3），旧版无任何清理，长期运行
    无限累积（单个数次 MB）。与 TTS 缓存清理同周期（1h）扫一次，6h 宽限保证回退响应
    与正在播放不被删，Windows 文件占用时跳过下轮再试；只认 `tts_` 前缀，绝不碰其他文件。
12. **sessions 临时文件改 pid+uuid 唯一名**。config/weather/role_news 早已改，唯独
    `PUT /api/sessions` 还用固定名 `sessions.tmp`：新旧进程交叠重启或杀软瞬时占用时
    会互相覆盖对方刚写好的替换源。
13. **`role_news_missing.log` 加大小轮转**。搜索长期无结果（冷关键词/引擎不可用）时
    该 JSONL 无限追加。超 1MB 保留尾部 256KB，按换行整行截断，绝不留半行 JSON。
14. **TTS singleflight 在飞条目加 64 上限**：正常使用远低于此，上限只兜凭据泄露后被
    刷接口的异常洪流，达到上限明确 503 而不是无限排队烧云端配额。
15. **多端同步 SSE 订阅加 100 上限**：每设备一条长连接，上限只兜连接泄漏/洪流
    （每条订阅带一个队列与广播成本），超限 503。

## 四、可观测性（零外部依赖，故障无需复现）

16. **LLM token 用量落盘，重启不清零**。进程增量按「每 50 次调用或每 5 分钟」节流
    写入 `data/llm_usage.json`（tmp+replace 原子写），启动时恢复历史基线，优雅关闭时
    补落最后一段；同时按供应商分桶（能看出钱烧给了哪家）。成本可观测从此跨重启连续。
17. **请求 ID + 慢请求/5xx 告警中间件**。每请求生成 12 位 `X-Request-Id`（接受上游
    传入但只放行 `[A-Za-z0-9_-]{1,32}`，防日志注入），响应头与 500 响应体都带，用户
    报错凭此 ID 可在日志定位唯一那次请求的完整 traceback。默认 WARNING 级别下平时零
    刷屏，只有普通 API >15s、`/api/chat` >300s（长文流式本就可能数分钟）、或响应 5xx
    时才打一条；`/api/sync/stream` 常驻长连接豁免。
18. **`/api/health` 增强**：数据盘总容量/剩余、在飞合成数、SSE 订阅者数、分供应商
    token 用量与起始统计时间（全部无敏感信息）。
19. **登录失败/锁定留痕**：公网隧道下的口令爆破此前日志里完全无痕。失败时 WARNING
    记录来源 IP 与连续失败次数（绝不记口令内容），锁定期间继续尝试也记录。
20. **安全响应头补 `Permissions-Policy`**：前端不使用摄像头/麦克风/定位/支付/USB
    （位置为手动配置文本、声音样本走文件上传，已全量检索确认），显式关闭这些浏览器
    能力，被注入第三方页面时无法借本域调用。

## 五、测试烧钱治理（本轮被记账功能抓出来的既有问题，最实质的"不加价"）

21. **跑测试会真实调用云端 LLM（七轮以来一直静默存在）**。记账功能上线后第一次跑
    验证就抓到了真实 mimo 扣费，来源有两个：
    - **QA 实例（`qa_run.py`）**：路径重定向发生在 `import server` 之后，config 仍指向
      真实文件，lifespan 启动预取角色动态时发真实搜索 + 云端总结（实测 4 次 /
      320 token）。QA 现统一关闭天气与角色动态的自动刷新/巡检/读时触发。
    - **离线测试套件**：直跑 `python test_xxx.py` / pytest 时 TestClient 起的是真实
      lifespan，读真实 config，激活角色开了动态自动刷新就会联网；另外第七轮已有的
      `test_server_helpers.test_usage_recorder` 直接调记账函数，第八轮给记账加了落盘
      后它会把测试数值写进真实 `data/llm_usage.json`。
    根治（三个测试入口全部覆盖，不依赖人的自觉）：
    - server.py 新增 `AI_DISABLE_EXTERNAL=1` 离线开关：lifespan 不调度天气/角色动态
      预取与巡检，`_bg_weather_refresh` / `_bg_role_news_refresh` 入口统一短路
      （含手动刷新端点与读时过期触发，保证测试零外部 HTTP、零 token）；用户显式
      发起的对话/搜索/TTS 不受影响。
    - `run_tests.bat` 内置该环境变量；`conftest.py` 在 import server 前 setdefault；
      7 个起 TestClient 的测试文件顶部各自 setdefault（开发者绕过 bat 直接
      `python test_xxx.py` 也安全）。
    - `test_usage_recorder` 落盘路径重定向临时目录、计数全局 finally 恢复。
    - 验证：官方 bat、pytest、直跑三种方式各跑一遍 18 套全绿，真实
      `data/llm_usage.json` 均不产生；QA 实例连续运行 + 全量冒烟 llm_usage 恒为 0。
    - `start_test_server.bat`（模拟器端到端实例）刻意**不**启用：那里要手工测全部
      功能（含手动刷新），它有独立 data-test 数据目录隔离。
