## 二、人设精简（用户授权：按最优方案；称呼以老公为主偶尔可换；事实查证后修正）

`config.json` 改前已整文件备份为 **`config.backup-before-prompt-r8.json`**（不满意可直接回滚）。

- **3293 → 2591 字（-21%，每轮对话省约 1000 token 的重复输入）**。现代指令模型不会因同一条规则重复 4 遍就多遵守 4 倍，重复只会烧 token、稀释其他指令注意力。
- **只合并重复，不改味道**：所有履历（入伍/榜眼/三连冠/六连冠/KWC 逆转/夏决 FMVP）、
  队友（轩染/钟意/长生/一诺）、游戏理解（苏烈王/视野压制/英雄推荐）、性格原话
  （「自主意识强」「一切都在情理之中」「蛋蛋」「高达」）逐字保留；亲密向段落的
  尺度与措辞原样保留——不加码、不削弱、不道德化删改。
- 称呼规则按裁定重写：主称呼永远「老公」，仅两人独处的极少数亲密时刻可偶尔换
  「宝贝」「我家那位」——两条指令不再互相否定。
- 「暖昧」3 处 → 暧昧；亚运 → 爱知·名古屋国家集训队（与《大帅2027人设档案 v0.3》口径一致）。
- 与系统层分工：人设不再复制系统固定注入的服从铁律全文。

## 三、代码层（输出文案逐字节等价，纯结构收敛）

1. **动态提示词组装单一真源**：新增 `_build_role_context()`（角色上下文块，
   chat/greeting 共用）与 `_assemble_dynamic_hints()`（动态段序列：事实块→
   自况/现实动态/位置/天气引用式指令→剧情→时间收尾）。两条链路物理拷贝消除，
   以后调 hint 顺序只改一处。
2. **剧情引擎常量化**：`STAGE_NAMES` / `STAGE_SHORT`（4 阶段名与一句话简述唯一
   来源，注入文本与前端 payload 共用）；`DATE_JOIN / DATE_CAMP /
   DATE_SEASON_START / DATE_ANNUAL_FINAL / DATE_SEASON_END` 取代散落的硬编码日期。
   所有 `_day_guide` / `story_context` / `day_info` / `jump` / `_update_stage`
   改引用常量，注入文本与改前完全一致。
3. **flag 枚举单一真源**：`role_engine.STORY_FLAGS = ("command_win","confession")`，
   后处理标注器、剧情识别器、剧情 API 三处校验统一引用。两套 SYSTEM 长文案
   **刻意不合并**——识别器有「正式比赛/排除训练赛」等场景化细则，强行共享会
   降精度；只统一真正的枚举硬逻辑。

## 四、新增质量门 `test_prompt_quality.py`（45 项，含第二阶段追加的标注器裁剪契约）

锁定内容资产的质量契约，防回流：
- 人设：长度区间、错别字黑名单（暖昧）、事实口径（名古屋，禁杭州亚运回流）、
  称呼不矛盾、**18 个履历/队友/英雄锚点 + 4 句性格原话**（手抖删掉即测试失败，
  角色不会悄悄"失忆"）、规则重复度上限。
- 提示词：动态段为确定性纯函数；注入顺序契约（事实块开头、时间块收尾、
  剧情在时间之前）；引擎关闭时空上下文不抛错。
- 剧情：阶段常量 4 档、日期边界严格有序；铺垫/官宣/训练/休赛/事件/比赛日
  （含待赛/已赛/取消三态）指引内容断言；前端 payload 阶段名来自常量。
- flag：未知节点被统一枚举拒绝、合法节点通过。

## 六、过程中的重要发现：云盘同步在合并另一设备的改动

本项目跑在移动云盘同步盘上。本轮工作中两次观察到**另一设备对同批文件的写入
被同步进来**：① `llm_chat` 签名 `max_tokens: int = 768` 一度残缺成
`max_tokens: 768`（语法错误，模块无法导入，非本轮编辑触碰）；②
`test_server_helpers.py` 出现与本轮重构同方向的新版本断言。当前磁盘版本已
一致且全绿，但建议：**不要在两台设备上同时开 AI 改这个项目**；关键节点用
`run_tests.bat` 跑一遍（语法损坏时会第一时间红）。

## 六·五、追加深挖（同日第二阶段：按"模型实际看到的完整提示词"审计）

在第一阶段结构收敛后，离线渲染了大帅每轮对话真正发给模型的完整 system prompt
（3589 字固定段 + 时间锚点）做跨层审计，又挖出两处实质问题：

4. **对话后处理标注提示词按角色裁剪（每轮非寒暄对话省 278 字 / 48%，并防串戏）**。
   `PostProcessor.SYSTEM` 原本恒定带约 185 字的 2027 剧情标注指令（岚风/比赛结果/
   指挥权/表白）。而大帅恋人线（dashuai）、小拟都不是剧情角色，这段指令每轮
   白发给标注模型——既多烧 token，又把**另一个角色名「岚风」**塞进大帅的标注
   上下文（虽然 set_flag 对非剧情角色不生效，不会误记剧情，但无关角色名会稀释
   标注注意力）。现 `PostProcessor(llm, include_story=...)` 按角色构造：
   - 非剧情角色 574 → **296 字**（去掉 story_result/story_flag 字段、示例、指令），
     情绪/精力/记忆核心标注原样保留；剧情版与改造前**逐字节一致**（AST 抽取
     git HEAD 旧常量比对验证）。
   - server 的单例工厂改为按 `_story_role()` 分桶缓存两个实例，角色运行时切换
     （dashuai ↔ dashuai2027）自动换提示词；默认构造仍含剧情段，既有直调方/
     测试零改动；`_parse` 对缺 story 字段的 JSON 始终容错。
5. **剧情识别器 flag 名插值枚举常量**：`_STORY_RECOGNIZER_SYSTEM` 里手写的
   `command_win/confession` 改为从 `role_engine.STORY_FLAGS` 插值，枚举改名时
   提示词自动跟随；JSON 示例大括号成对（无 f-string 转义残留，有测试锁定）。
6. **审计后确认无需改的项（附结论，避免后人重复怀疑）**：
   - 主动问候前端已有完善节流（每设备每天 ≤1 次 + 距上次聊天 >2h），不加服务端限制。
   - 系统时间在「system 尾部引用式 + 用户消息锚点」双注入是刻意设计（引擎开启时
     system 段只引用不复述，不构成重复）。
   - 人设内「男生本色/不嗲/不端着」在亲密、氛围、说话三个场景各出现一次，是
     分布式护栏而非重复（模型最易在此翻车，`_fix_addressing` 整个正则群即兜底），保留。
   - 安全底线「不违法、不伤害别人」经定位在人设中只出现 1 次（一句两个关键词），无内部重复。
   - 剧情 STAGE_GUIDE / 铺垫期三段引导 / 搜索注入防指令 / 视觉诚实降级提示
     逐条复核，无矛盾、无事实错误，不动。

第二阶段新增质量断言 11 项（test_prompt_quality 共 45 项），全套 19 套离线测试
+ 21 项运行时冒烟仍全绿。
